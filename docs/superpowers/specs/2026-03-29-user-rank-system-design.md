# ユーザーランク・スコア管理システム設計

GitHub Issue: #44

## 概要

問題の正解数や出題案の作成・承認数に応じて経験値を付与し、ランクを上昇させるゲーミフィケーション機能。ランクに応じて「あなたはxxを扱えます！！」（化学物質の危険度が上がっていく）を表示し、ユーザーのモチベーションを促進する。

## 要件

### 経験値の付与対象

| アクション           | 付与量            | 説明                                         |
| -------------------- | ----------------- | -------------------------------------------- |
| ドリルセッション完了 | 基本10 + 正解数×2 | 10問全問正解で30exp                          |
| 出題案の提出         | 30                | 出題案を提出（レビュー依頼）したとき         |
| 出題案の承認         | 50                | 管理者が出題案を承認したとき（作成者に付与） |

3つのアクションは均等な重みで設計。頻度差を付与量で調整。

### ランク定義

20段階、ハードコード。化学物質の危険度が上がっていく構成。

| ランク | 必要累計Exp | 化学物質                | カテゴリ   |
| ------ | ----------- | ----------------------- | ---------- |
| 1      | 0           | 水 (H₂O)                | 日常物質   |
| 2      | 50          | 食塩 (NaCl)             | 日常物質   |
| 3      | 120         | 重曹 (NaHCO₃)           | 日常物質   |
| 4      | 200         | エタノール (C₂H₅OH)     | 日常物質   |
| 5      | 300         | 酢酸 (CH₃COOH)          | 日常物質   |
| 6      | 420         | 過酸化水素 (H₂O₂)       | 一般薬品   |
| 7      | 560         | アンモニア (NH₃)        | 一般薬品   |
| 8      | 720         | 塩酸 (HCl)              | 一般薬品   |
| 9      | 900         | 硫酸 (H₂SO₄)            | 一般薬品   |
| 10     | 1100        | 水酸化ナトリウム (NaOH) | 一般薬品   |
| 11     | 1350        | 硝酸 (HNO₃)             | 劇物       |
| 12     | 1650        | ホルムアルデヒド (HCHO) | 劇物       |
| 13     | 2000        | クロロホルム (CHCl₃)    | 劇物       |
| 14     | 2400        | フッ化水素 (HF)         | 毒物       |
| 15     | 2850        | 黄リン (P₄)             | 毒物       |
| 16     | 3350        | シアン化カリウム (KCN)  | 毒物       |
| 17     | 3900        | ヒ素 (As)               | 毒物       |
| 18     | 4500        | 水銀 (Hg)               | 特定毒物   |
| 19     | 5200        | VXガス                  | 特定毒物   |
| 20     | 6000        | プルトニウム (Pu)       | 最終ランク |

**バランス目安**: ドリルのみ全問正解ペースでランク10まで約37セッション。ランク20到達はドリル約200セッション相当。出題案も活用すればより早く到達可能。

### 経験値管理方式

イベント駆動でリアルタイム加算。各アクション実行時にユースケース内で経験値をDBに加算し、ランクアップ判定を行う。

### 表示場所

既存のStats（統計）ページに統合。

### ランクアップ演出

- リッチなモーダル演出（オーバーレイモーダル + CSSアニメーション）
- 表示タイミング: 次回ドリル完了時にまとめて表示
  - 出題案の承認など、ユーザーが不在時のランクアップはDBに記録し、次回ドリル完了時に演出

## データモデル

### `user_experience` テーブル

ユーザーの経験値累計とランク状態。

| カラム      | 型                  | 説明                 |
| ----------- | ------------------- | -------------------- |
| userId      | UUID, PK, FK → user |                      |
| totalExp    | INT, default 0      | 累計経験値           |
| currentRank | INT, default 1      | 現在のランク (1〜20) |
| updatedAt   | TIMESTAMP           |                      |

初回経験値付与時に upsert でレコードを作成する。

### `experience_logs` テーブル

経験値付与の履歴。内訳追跡・バランス調整・デバッグ用。

| カラム      | 型                                                       | 説明                          |
| ----------- | -------------------------------------------------------- | ----------------------------- |
| id          | UUID, PK                                                 |                               |
| userId      | UUID, FK → user                                          |                               |
| action      | ENUM: drill_complete, proposal_submit, proposal_approved | 付与理由                      |
| amount      | INT                                                      | 付与量                        |
| referenceId | UUID                                                     | 対象のsessionId or proposalId |
| createdAt   | TIMESTAMP                                                |                               |

- インデックス: `[userId]`, `[userId, action]`
- ユニーク制約: `(userId, action, referenceId)` — 二重付与防止

### `rank_up_events` テーブル

ランクアップの通知管理。

| カラム       | 型                  | 説明           |
| ------------ | ------------------- | -------------- |
| id           | UUID, PK            |                |
| userId       | UUID, FK → user     |                |
| newRank      | INT                 | 到達したランク |
| previousRank | INT                 | 直前のランク   |
| displayedAt  | TIMESTAMP, nullable | null = 未表示  |
| createdAt    | TIMESTAMP           |                |

- インデックス: `[userId, displayedAt]` — 未表示イベント検索用

## バックエンド設計

### ドメイン層

**新規エンティティ: `UserExperience`**

- ランク定義テーブル（定数配列）を保持
- `addExp(amount)` — 経験値加算＋ランクアップ判定。ランクアップがあった場合はその情報を返す
- `getRank()` — 現在のランクと化学物質情報を返す
- `getNextRankExp()` — 次のランクまでの必要経験値を返す
- `getProgress()` — 現在ランク内の進捗率（0〜100%）を返す

### アプリケーション層

**新規ユースケース:**

- `AddExperience` — 経験値を加算し、ランクアップがあれば `rank_up_events` を作成。`experience_logs` に履歴を記録。二重付与は `(userId, action, referenceId)` ユニーク制約で防止し、try-catch で処理
- `GetUserRankInfo` — ユーザーのランク情報を返す（totalExp, currentRank, 化学物質名, カテゴリ, 進捗率, 次ランクまでのexp）
- `GetPendingRankUps` — 未表示のランクアップイベントを取得（`displayedAt IS NULL`）
- `MarkRankUpDisplayed` — ランクアップ演出表示後に `displayedAt` を更新

**既存ユースケースへの組み込み:**

- `SaveDrillSession` → 保存後に `AddExperience(drill_complete, sessionId, 基本10 + 正解数×2)` を呼ぶ
- `SubmitQuestionProposal` / `SubmitQuestionProposalByUser` → 提出後に `AddExperience(proposal_submit, proposalId, 30)` を呼ぶ
- `ApproveQuestionProposal` → 承認後に、承認された出題案の作成者に `AddExperience(proposal_approved, proposalId, 50)` を呼ぶ

### プレゼンテーション層

**新規APIエンドポイント:**

- `GET /api/rank` — 現在のランク情報（totalExp, currentRank, 化学物質名, カテゴリ, 進捗率, 次ランクまでのexp）
- `GET /api/rank/pending-rank-ups` — 未表示のランクアップイベント一覧
- `POST /api/rank/mark-displayed` — ランクアップ演出の表示済みマーク。body: `{ rankUpEventIds: string[] }`

全エンドポイントは `requireAuth` ミドルウェアで保護。

## フロントエンド設計

### Statsページへの統合

既存の `/stats` ページの上部にランク情報カードを追加。

**ランク情報カードの表示内容:**

- 現在のランク番号と化学物質名（例: "Rank 12 — ホルムアルデヒド (HCHO)"）
- 化学物質のカテゴリラベル（例: "劇物"）
- 累計経験値の表示
- 次のランクまでのプログレスバー（例: "1650 / 2000 exp — あと350"）
- 「あなたはホルムアルデヒドを扱えます！！」のメッセージ

**データ取得**: `useQuery` で `GET /api/rank` を呼び出し。

### ランクアップ演出モーダル

**トリガー**: ドリル完了時のリザルト画面表示時に `GET /api/rank/pending-rank-ups` を呼ぶ。未表示のランクアップがあれば演出を開始。

**演出内容:**

- オーバーレイモーダル
- 「ランクアップ！」のタイトルアニメーション
- 新しいランク番号と化学物質名を大きく表示
- 「あなたは○○を扱えるようになりました！！」のメッセージ
- 化学物質のカテゴリに応じた色分け:
  - 日常物質: 緑
  - 一般薬品: 青
  - 劇物: オレンジ
  - 毒物: 赤
  - 特定毒物: 紫
  - 最終ランク: ゴールド
- 複数ランクアップが一度に起きた場合は順番に表示（「次へ」ボタン）
- モーダルを閉じたら `POST /api/rank/mark-displayed` を呼ぶ

**実装方針**: CSS アニメーション（`@keyframes`）で実装。外部アニメーションライブラリは使わない。

**データ取得**:

- `useQuery` で `GET /api/rank/pending-rank-ups` をドリル完了時に呼び出し
- `useMutation` で `POST /api/rank/mark-displayed` をモーダル閉じ時に呼び出し
